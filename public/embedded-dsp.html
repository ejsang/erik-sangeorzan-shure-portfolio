Embedded Audio Separation of Human Voices

Platforms
Teensy and Raspberry Pi Linux
Languages
C/C++ and Python
System work

My contribution
Windowing and splicing algorithms

The team system

The team built an embedded pipeline for capture, streaming, independent component analysis (ICA), and playback. Teensy-side I2S capture and UART streaming connected to Python processing on Raspberry Pi Linux, with multiprocessing and GPIO synchronization in the project system.

I implemented windowing and splicing algorithms within the processing workflow. The hardware, firmware, transport, processing, and playback system was a team effort.

Result and prototype limits

The team demonstrated separation of linear mixtures. Live microphone mixtures in a room were not successfully separated. The report also documents seconds of delay, stutter, and data-loss limitations in the pipeline.

The useful evidence is integration across embedded capture, transport, Linux processing, and audio validation, with a bounded DSP result.

Audio within a constrained system

The four-person team built a musical synthesizer with sampled instruments and layer recording/playback. My documented contributions were layering, additional peripheral-driver routines, and memory implementation.

The system used memory-mapped command/response routines for peripheral access. This provides academic evidence of low-level integration and audio/memory work on the E100 platform.

Ownership and scope

Instrument, interface, and synthesis work was shared across the team. The personal contribution stated here follows the project’s documented work allocation.

STM32L4 Zumo Autonomous Navigation

Platform
STM32L4 with Zumo hardware
Language
C with STM32 HAL
Control and interfaces
ADC, GPIO, timer input capture, PWM, and LPUART
Project scope
Obstacle-course navigation toward a light source; separate line-following extension

Navigate toward the light

The central task was to navigate an obstacle course autonomously and reach a light source. The team’s robot scanned light levels through ADC inputs, used distance sensing to detect obstacles, and controlled turning and movement with PWM motor outputs.

The navigation program combined servo scanning, timer input capture for distance measurements, and LPUART telemetry. Buzzer and LED feedback were also part of the project.

Line-following extension

A separate program implemented a polling line follower using six reflectance-sensor inputs and weighted motor correction, with TIM4 PWM motor control and LPUART telemetry.

What the project adds

Both parts connect sensor readings, embedded C/HAL code, and physical motion. Navigation and line following were distinct implementations within the same two-person academic project.

The professional context

These prototypes reinforce the domain connection. The central professional examples remain the Android audio rotation and sustained C++ systems work.
